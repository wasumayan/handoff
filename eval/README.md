# Evaluating handoff

The question: when a coding session moves from one agent to another (Claude Code to Codex, or the
reverse), does a handoff let the next agent finish the job better, faster, or cheaper than no handoff
or a pasted transcript? And which version or setting of the tool does that best?

Everything here runs on synthetic scenarios. No personal data is involved.

## What gets compared

**Variants** (`eval/variants.toml`) decide what the next agent reads:

| variant | what the recipient gets |
|---|---|
| `none` | only the original task, as a user would retype it |
| `raw` | the whole previous transcript pasted in |
| `ideal` | a hand-written handoff per scenario: the upper bound |
| `dump`, `dump-2k`, `dump-8k`, `dump-64k` | `handoff create --no-llm` at the default and at fixed budgets |
| `dump-base` | the tool as of commit `39231ee`, before the parser and compaction fixes |
| `adapted` | `handoff create` with the model-written next steps (needs a backend) |

Add a variant by adding a table. `ref = "<commit or tag>"` runs an older version of the tool on the
same inputs (checked out under `eval/.cache/refs/`), so versions compare directly.

**Scenarios** (`eval/scenarios/`): five small repos, each stopped at a midpoint of an authored session.
Each one hides information that exists only in that session, so a recipient with no handoff cannot
pass by reading the repo:

| scenario | only in the session | dead end tried | user correction mid-session |
|---|---|---|---|
| 01_verbose_flag | `basicConfig` is a no-op here | `basicConfig(level=DEBUG)` | also log to `debug.log` |
| 02_percent_bug | root cause in `stats.percent` | `parse.py` ruled out | keep the signature, round to 2 decimals |
| 03_rates_refactor | the API returns the rate as a string | `urlopen(url, 5)` sent a POST | `Decimal`, not float; `RateError.currency` |
| 04_report_long | trailing-space ids; ambiguous dates | pandas unavailable | dates are DD/MM; sort order |
| 05_snapshot_trap | the EU number format | updating the snapshot | never update snapshots |

`04` is long (~90k chars raw) and ends abruptly with no summary, so compaction settings matter there.
Every session exists in Claude Code and in Codex format, generated by
`eval/scenarios/build_sessions.py`.

**Agents**: `claude` (Claude Code CLI), `codex` (Codex CLI), `standin` (a small tool-calling loop
against any OpenAI-compatible endpoint), `fake` (copies the reference solution; checks the harness
only). By default sessions cross agents: Codex sessions go to Claude Code and Claude Code sessions go
to Codex. Same-agent pairs measure little, because the recipient already reads the source's
instruction file.

## Metrics

Per run (one scenario x source x agent x variant x repeat):

| metric | meaning |
|---|---|
| `pass 1st` | hidden tests pass after the agent's first invocation |
| `pass` | hidden tests pass after up to `--max-nudges` nudges |
| `nudges` | times the run had to be resumed with "No further input is available; use your judgment and finish" because tests failed or it ended on a question. **Manual inputs a user would have had to give.** |
| `questions` | times the agent stopped to ask (AskUserQuestion calls, a final message ending in `?`, or `ask_user` for the stand-in) |
| `prefs ok` | project rules respected (e.g. a file left untouched), checked from the final tree |
| `redo` | repeats of a known dead end or of finished work (e.g. retrying pandas, rewriting the snapshot) |
| `turns`, `tool calls` | agent steps |
| `input tok` | uncached + cache-read + cache-write input tokens, summed over the run |
| `output tok` | output tokens |
| `peak ctx` | largest single model call's input: the context window the run needed (Claude Code, Codex, stand-in) |
| `agent s` | wall time of the agent |
| `cost`, `cost/pass` | USD as reported by the CLI (Claude Code only) |
| `leaks` | runs whose commands, file reads or transcript mention the eval checkout (where solutions and hidden tests live). A pass there is suspect: inspect it or drop it |

Per handoff, with no model involved (`score`): size in chars and estimated tokens, and **recall**:
the share of the scenario's session-only facts, user corrections and dead ends the handoff text
contains (regexes in each `checks.json`).

The report prints mean ± standard error, a pass count per scenario, and a table pairing each variant
against `none` on the same scenario, source, agent and repeat.

## Setup

```bash
git clone https://github.com/wasumayan/handoff && cd handoff
git checkout claude/happy-mayer-tnvnhz
uv sync --extra dev                # Python 3.11+, installs pytest and ruff from uv.lock
uv run pytest -q                   # everything should pass
```

Install the agent CLIs you want to evaluate (Claude Code: `claude`; Codex: `codex`) and set keys:

```bash
export ANTHROPIC_API_KEY=...       # for --agent claude
export OPENAI_API_KEY=...          # for --agent codex
# for the `adapted` variant, --judge and --agent standin: any OpenAI-compatible endpoint
export HANDOFF_BASE_URL=https://api.openai.com/v1 HANDOFF_MODEL=<model> HANDOFF_API_KEY=$OPENAI_API_KEY

uv run python eval/run.py doctor          # what is missing
uv run python eval/run.py doctor --live   # one tiny paid call per CLI, run the same way the eval does
```

By default each agent run gets fresh, empty config directories (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`).
Your own memory, instruction files, MCP servers and hooks stay out of the measurement, and runs stay
out of your history. Auth then comes from the API keys. `--no-isolate` uses your normal login and
config instead (fine for a smoke test, not for numbers).

**Safety.** The agents edit files and run shell commands without asking. Codex runs in its
workspace-write sandbox. Claude Code runs with `acceptEdits` and Bash allowed, and is not sandboxed.
Work happens in temp directories outside the repo, but run the eval in a VM or container if that
matters to you.

## Running

```bash
uv run python eval/run.py score --out eval/out/score          # free, seconds: handoff content per variant

# calibrate cost and time on one cell before anything big
uv run python eval/run.py run --agent claude --scenarios 01 --variants dump --out eval/out/try

uv run python eval/run.py plan --agent claude --runs 3        # the matrix and run count
uv run python eval/run.py run  --agent claude --runs 3 --out eval/out/claude
uv run python eval/run.py run  --agent codex  --runs 3 --out eval/out/codex
uv run python eval/run.py report eval/out/claude
```

`run` is resumable: rerun the same command with the same `--out` and finished cells are skipped
(`--rerun` redoes them). Each cell keeps `result.json`, the exact `handoff.md` the agent saw, the
`final.diff`, and the end of the agent transcript. Useful flags: `--variants none,dump,ideal`,
`--scenarios 01,04`, `--sources codex`, `--model`, `--timeout`, `--max-nudges`,
`--agent-arg <extra CLI arg>`, `--judge` (grades each scenario's rubric with the backend model),
`--max-budget-usd` (Claude Code spend cap per invocation, default 2.0; Codex has no equivalent, so
`--timeout` bounds it).

A full run is 5 scenarios x 1 source x 8 variants x 3 repeats = 120 agent runs per agent, plus
nudges. Use the calibration run to estimate cost before starting one.

## Reading the results

- Start with the paired table. A variant is worth something if it raises `pass` or lowers `nudges`
  against `none`, and the token and time columns say what that cost.
- `ideal` is the ceiling and `none` the floor. Where a variant sits between them on `pass`, and how
  much smaller it is than `raw`, is the result.
- Compare `dump-*` and `dump-base` to see what compaction settings and tool versions change, on
  identical inputs.
- The per-scenario table shows where differences come from. Five scenarios is a small n: treat a
  difference of one run as noise.

## Adding scenarios

Create `eval/scenarios/NN_name/` with `task.md`, `repo/` (rules file named `CLAUDE.md`), `hidden/`,
`solution/`, `ideal.md` and `checks.json` (copy one). Write its session as a function in
`build_sessions.py` and add it to `SCRIPTS`. Then run `uv run python eval/scenarios/build_sessions.py`
and `uv run pytest -q`. The tests check that the midpoint fails and the solution passes, that the
committed sessions match the generator, and that recall is 0 with no handoff and 100% for `ideal` and
`raw`.

A scenario discriminates only if passing needs something said in the session: a fact found, a
correction from the user, a dead end. Rules written in the repo's own `CLAUDE.md` are visible to every
variant, so they are controls, not tests.

## Limitations

- The sessions are authored, not recorded. To use a recorded one, replace `source/*.jsonl`, with the
  working directory rewritten to `/WORKDIR`.
- Recall is regex-based. A model-written handoff that paraphrases can score lower than it deserves.
  Use `--judge`, or read the saved `handoff.md`.
- Codex reports no cost. Its `peak ctx` comes from the rollout file it writes per session.
- The `adapted` variant, the stand-in agent and the judge share one backend model.
- Agent behaviour varies run to run. Use `--runs 3` or more before drawing conclusions.
